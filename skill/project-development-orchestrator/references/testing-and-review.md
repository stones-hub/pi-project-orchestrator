# 测试、本机候选验收与复审

## 完成定义

编码 Agent 自报、单元测试、进程存活、容器 running 或单独 `/health` 成功，都
不能单独证明候选可用。改变运行行为的任务至少需要：

1. Pi 对照方案检查完整 Git 差异；
2. Pi 独立重跑相关自动化测试；
3. 当前候选重新构建或安装并达到业务就绪；
4. 从正式入口完成核心黑盒业务场景；
5. 最终响应/页面/文件/测试数据库结果正确，运行日志无未解释异常。

纯文档修改可以免除本机运行验收，但任务书和交接必须写明理由。

## 普通任务与关键任务

只保留两档，按最坏业务后果判断；无法判断时先按关键任务处理并向用户说明。

| 类型 | 典型范围 | 最低验证 |
|---|---|---|
| 普通任务 | 文案、样式、局部交互、普通业务逻辑和一般查询 | 相关测试 + Pi 完整 diff 检查；改变运行行为时做对应的本机候选运行验收 |
| 关键任务 | 权限/认证、资金、删除或生产数据、并发/锁/状态机、数据库迁移、安全边界、发布/灰度/回滚/恢复、核心共享契约 | 普通任务全部要求 + 更完整受影响测试 + 关键失败/边界/恢复场景 + 至少一路独立复审 |

关键任务的验证强度、关键场景和复审范围在编码前写进任务书并与用户确认。任务
执行中若范围扩大或触及关键契约，停止并重新确认，不静默降档。

## 本机候选运行方式

统一验收目标，不统一工具：

| 项目形态 | 推荐方式 |
|---|---|
| 容器化交付 | Docker Compose 重新 build 后启动；使用独立 project name 和隔离 volume |
| Python/Java/Go 服务 | 启动当前虚拟环境、JAR 或二进制；MySQL/Redis 等依赖可单独用容器 |
| 前后端 Web | 后端按真实方式启动；前端验证正式 build，由本地服务器托管并走浏览器场景 |
| CLI | 构建并安装到干净临时环境，从命令行公开入口调用 |
| SDK/库 | 先打包再装入干净环境，通过公开 API 调用，不从源码目录直接 import 冒充安装 |
| 桌面应用 | 构建真实应用或安装包后运行 |
| 无法本机等价运行 | 使用编码前已批准的隔离测试环境；没有条件则标记“验证受阻” |

数据库场景使用与目标环境一致的数据库类型和主版本；项目使用 MySQL 时不得用
SQLite 冒充。第三方服务可使用明确批准的本地替身，但不得 mock 掉本任务真正要
证明的契约。

## 四类必须证据

- **候选身份**：构建来自当前工作区；记录 Git 基线/工作区状态、构建命令和产物
  身份。不得复用无法证明来源的旧镜像、旧二进制或旧前端制品。
- **业务就绪**：应用及依赖可提供服务；不仅是 PID、端口或容器存活。
- **黑盒业务场景**：从真实调用方会使用的入口走核心成功场景；关键任务补充失败、
  权限、并发、幂等或恢复场景。
- **最终结果**：核对响应、页面、文件或数据库，并检查日志不存在未解释异常。

前端行为需要真实浏览器动态验收，不能只凭静态 HTML 或截图断言交互正确。

## 隔离和清理

- 默认监听 `127.0.0.1`，使用独立端口、临时目录、测试数据库和合成数据。
- 不读取生产凭证，不连接生产数据库或生产服务，不覆盖正在使用的本地服务。
- 容器方式隔离 Compose project 和 volume；原生方式隔离进程、端口和数据目录。
- 测试结束清理本次资源。若失败现场需保留，在交接中写清保留对象、原因和后续
  清理责任。
- 安装全局软件、修改系统配置、连接外部机器/环境、SSH 或使用真实凭证前另行
  获取授权。

## 结果失效和失败处理

- 代码、测试、配置、依赖或构建输入变化后，旧本机验收失效。
- 构建、就绪、业务场景、最终结果或日志任一不合格，均不得声明候选通过。
- 自动化测试全绿不能覆盖黑盒失败；黑盒成功也不能覆盖计划内测试失败。
- 方案问题回讨论；实现问题交原编码 Agent 窄修；环境问题写“受阻”。
- 窄修后 Pi 重新检查差异、重跑受影响测试并重新构建、重验当前候选。

## 独立复审

- 必须使用 `--mode review` 新会话，不带 `--resume`。
- 复审提示写清方案、任务书、候选范围、关键契约和关注点，不让复审器猜。
- 普通任务可由 Pi 本地收口；关键任务至少一路独立复审，必要时换执行器以减少
  同源盲区。
- 复审发现具体阻断时，先复现，再交原编码 Agent 窄修，最后重跑失效的验证。
- 复审是定性检查，不能替代 Pi 自己的 diff、测试和本机运行验收。

## HANDOVER 必须分开的状态

1. 方案：讨论中 / 已确认 / 已获编码授权；
2. 本机候选：Agent 自报 / Pi diff / 自动化测试 / 构建或安装 / 启动就绪 /
   黑盒业务验收 / 结果与日志 / 受阻项；
3. Git：未提交 / 已提交 SHA / 已推送远程和分支；
4. 部署：未授权 / 已授权 / 目标机实际 HEAD / 健康 / 业务验证 / 生产验收；
5. 会话：executor / 请求模型 / 可证明的真实模型 / session_id / 当前基线。

这些状态互不蕴含：本机通过不等于已提交，已提交不等于已推送，已推送不等于
已部署，目标服务启动不等于业务验收通过，已部署不等于生产验收完成。
